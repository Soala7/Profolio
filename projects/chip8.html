Overview

This is a CHIP-8 emulator written in C using SDL2 for graphics and audio. CHIP-8 is an interpreted programming language developed in the 1970s for early microcomputers and homebrew gaming. This emulator implements the full CHIP-8 instruction set, including CPU emulation, memory management, display rendering, input handling, and audio output.

How the Emulator Works

The emulator follows a classic fetch-decode-execute cycle:

fetch — read opcode from RAM at PC
↓
decode — extract operation, X, Y, N, NN, NNN
↓
execute — perform the operation
↓
update — timers, display, audio
↓
repeat — at 700 Hz (standard CHIP-8 speed)

Features

Full CHIP-8 instruction set (35+ opcodes)
64x32 pixel monochrome display
4KB RAM with font storage
16 general-purpose registers (V0–VF)
16-level stack for subroutine calls
Delay and sound timers (60 Hz)
Hex keypad input (0–F)
Audio output via SDL2
Resizable window with pixel scaling
Pause/resume with SPACE

Accurate timing with performance counters

Implementation Details

1. Memory & Font Loading

The emulator allocates 4KB of RAM (4096 bytes). The first 512 bytes (0x000–0x1FF) are reserved for the interpreter, with the font data stored at 0x000. The font data contains 16 sprites (5 bytes each) for digits 0–9 and letters A–F. Programs are loaded starting at address 0x200. 

// Font data stored starting at 0x000 in RAM
const uint8_t font[] = {
    0xF0, 0x90, 0x90, 0x90, 0xF0, // 0
    0x20, 0x60, 0x20, 0x20, 0x70, // 1
    // ...
};
memcpy(&chip8->ram[0], font, sizeof(font));

2. Instruction Decoding

Each CHIP-8 instruction is 2 bytes (16 bits). The emulator fetches the opcode from RAM, then decodes it using bitwise operations to extract the operation and operands. 

uint16_t opcode = (chip8->ram[chip8->PC] << 8) | chip8->ram[chip8->PC + 1];
chip8->PC += 2;

chip8->inst.NNN = opcode & 0x0FFF;  // 12-bit address
chip8->inst.NN  = opcode & 0x00FF;  // 8-bit value
chip8->inst.N   = opcode & 0x000F;  // 4-bit nibble
chip8->inst.X   = (opcode >> 8) & 0x0F;  // First register
chip8->inst.Y   = (opcode >> 4) & 0x0F;  // Second register

3. Display & Rendering

The display is a 64x32 pixel monochrome grid. Pixels are stored in a boolean array and rendered using SDL2 rectangles. The emulator scales the display to fit the window size while maintaining the aspect ratio.

4. Input Handling

The emulator maps PC keyboard keys to the CHIP-8 hex keypad (0–F). The key mapping follows the standard layout:

1 2 3 4 → 1 2 3 C
Q W E R → 4 5 6 D
A S D F → 7 8 9 E
Z X C V → A 0 B F

5. Audio

The sound timer is updated at 60 Hz. When the sound timer is greater than 0, the emulator plays a 440 Hz square wave using SDL2's audio callback. The audio output is paused when the timer reaches 0.

6. Timing

The emulator uses SDL's performance counters for accurate timing. Instructions are executed at approximately 700 Hz (standard CHIP-8 speed), while timers are updated at 60 Hz. This creates authentic emulation behavior.

Challenges

  • Understanding the bitwise operations needed to decode instructions
  • Implementing the display rendering with proper pixel scaling
  • Getting the audio callback to work correctly with SDL2
  • Maintaining accurate timing between instruction execution and timer updates
  • Debugging the shift instructions (8xy6 and 8xyE) which have different behaviors in CHIP-8 and Super-CHIP

Limitations

  • No Super-CHIP support (extended instructions)
  • No SCHIP (Super CHIP) mode with higher resolution
  • No support for the CHIP-8X extended instruction set
  • Simple audio — only generates a square wave
