Overview

This is a minimal Unix shell written in C. It reads commands from the user, parses them, and executes them — either as built-in commands or by launching external programs. The shell demonstrates core operating-system concepts including process creation, inter-process communication, and file descriptor manipulation.

How a Shell Works

When you type ls into the shell, it doesn't know how to list files itself. Instead, it performs these steps:

User input
↓
read_line() — reads command from stdin
↓
split_line() — tokenizes with strtok()
↓
execute() — checks for built-ins, pipes, redirection
↓
Built-in? ── Yes → built-in function
│
No
↓
launch()
↓
fork() — creates a child process
↓
execvp() — replaces child process with the program
↓
waitpid() — waits for the child to finish
↓
Shell accepts next command

Features

Built-in commands (cd, help, about, exit)
External program execution via execvp()
Process creation with fork()
Process synchronization with waitpid()
Pipes (|) using pipe() and dup2()
Output redirection (>, >>)
Input redirection (<)
Dynamic command parsing with strtok()
Memory management with malloc() / realloc()
Filesystem interaction via chdir()
Error handling with perror()

Implementation

1. Reading Input

The shell reads commands using read_line(), which dynamically allocates memory and grows the buffer as needed. It reads character by character until a newline or EOF is encountered.

2. Tokenizing Commands

split_line() uses strtok() to split the input string into an array of arguments. The delimiter set includes spaces, tabs, newlines, and carriage returns.

3. Built-in Commands

The shell implements four built-in commands: cd (change directory), help (show available commands), about (show project info), and exit (terminate the shell).

4. Process Creation

For external commands, the shell uses fork() to create a child process, then execvp() to replace the child's memory with the requested program. The parent waits for the child to finish using waitpid().

5. Pipes

The shell supports single pipes using pipe(). It creates two child processes: one writes to the pipe, the other reads from it. dup2() is used to redirect stdout and stdin to the appropriate pipe ends.

6. Redirection

The shell handles three types of redirection:

  • > — redirect stdout to a file (overwrite)
  • >> — redirect stdout to a file (append)
  • < — redirect stdin from a file

These are implemented using open() and dup2() to replace the standard file descriptors.

What I Learned

  • How Unix processes are created and managed with fork() and exec()
  • How to interpret the encoded child-process status using WIFEXITED() and WIFSIGNALED()
  • How pipes work as a form of inter-process communication
  • How file descriptors can be duplicated and redirected
  • How to parse user input and handle dynamic memory allocation
  • How to implement built-in shell commands

Challenges

  • Understanding the difference between execvp() and system()
  • Managing memory correctly with malloc() and realloc()
  • Handling the edge cases in the parser (empty input, trailing spaces)
  • Debugging pipe and redirection issues with dup2()
  • Learning the waitpid() status encoding

Limitations

This is a learning project and has several limitations compared to full-featured shells like Bash or Zsh:

  • No support for quoted arguments (e.g., echo "hello world")
  • Only single pipes are supported (cmd1 | cmd2)
  • No support for 2> (stderr) redirection
  • No background job support (&)
  • No job control or signals handling
  • Simple parser — doesn't handle complex shell grammar

Future Improvements

  • Add support for quoted arguments
  • Support multiple pipes (cmd1 | cmd2 | cmd3)
  • Add 2> and 2>> redirection
  • Implement background execution with &
  • Add command history with up arrow
  • Add tab completion for filenames and commands
